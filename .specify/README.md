# .specify

This repo follows GitHub's [Spec-Driven Development](https://github.com/github/spec-kit)
methodology. This directory holds the machinery for it:

- `memory/constitution.md` — the nine articles governing this repo,
  adapted for a design-system domain. Supreme over `AGENTS.md` and
  `CONTRIBUTING.md` on any conflict. See `decisions/0006.md` for how and
  why this was adapted rather than copied verbatim.
- `templates/` — `spec-template.md`, `plan-template.md`,
  `tasks-template.md`, `checklist-template.md`. Use these for every new
  feature going forward. `specs/001-design-system-foundation/` is v1
  retrofitted into this structure — read it as a worked example before
  writing your first new one.

## An honest note on how this was built

This directory was hand-authored to match the structure documented in
[spec-driven.md](https://github.com/github/spec-kit/blob/main/spec-driven.md)
and the public template files, not generated by actually running the
`specify` CLI — the environment that built this repo had no network
access to `uv tool install specify-cli`. If you install the real CLI
(see the spec-kit README's Get Started section) and run
`specify init --here`, it may want to write its own copies of these
files (agent-specific prompt files under `.github/prompts/` or
`.claude/commands/`, helper scripts under `.specify/scripts/`, etc.).

Before letting it overwrite anything here: this repo's `constitution.md`
is real, ratified content specific to this project (see the Sync Impact
Report at its top) — not a placeholder template. Treat any CLI-driven
overwrite of `memory/constitution.md` the same way spec-kit's own docs
warn about (issue #391 in that repo covers exactly this failure mode):
back it up, run the installer, then reconcile by hand rather than
accepting a template overwrite of ratified principles.

## Using this without the CLI

Every command in spec-kit's workflow (`/speckit.specify`, `/speckit.plan`,
`/speckit.tasks`) is really just "fill out a template file in the right
place, in the right order, gated by the constitution." You can do this
by hand with any AI agent or on your own:

1. Copy `templates/spec-template.md` into a new
   `specs/00N-your-feature-name/spec.md`, fill it in, run
   `templates/checklist-template.md` against it.
2. Copy `templates/plan-template.md` into `plan.md` in the same folder.
   Do not skip the Constitution Check — an unchecked gate needs a
   justification in Complexity Tracking, not silent omission.
3. Copy `templates/tasks-template.md` into `tasks.md`, derived from the
   plan.
4. Work the tasks in order, respecting `[P]` markers.
